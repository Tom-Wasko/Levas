# Zadania dla sesji OpenCode – polecenia do wklejenia

Kolejność i cele: `notatki/Plan optymalizacji.md`. Sesje idą **po kolei** (A, potem B), bo B zmienia zasady i boty,
na których gra A. Na nowym komputerze najpierw `git clone https://github.com/Tom-Wasko/Levas.git` i uruchomienie
według `AGENTS.md`. Na początku każdej sesji agent robi `git pull --rebase origin main`.

## Sesja 1 – część A (Fable 5.1)
```
Przeczytaj AGENTS.md i notatki/Plan optymalizacji.md, a potem wykonaj zadanie z pliku
zadania/A_analiza_gracza.md (A1–A3). Pracuj samodzielnie, po każdym kroku commit i push.
Kodu gry nie zmieniaj. Na końcu daj mi krótkie podsumowanie raportu.
```

## Sesja 2 – B1, B2, zmiany zasad Z, B3 i B4 (Opus 5.5 high albo Fable 5.1, po zakończeniu A)
```
Przeczytaj AGENTS.md, notatki/Plan optymalizacji.md i zadania/B_kalibracja.md. Wykonaj po kolei
B1, B2, Z1–Z7, B3 (część potrzebna do pomiaru) i B4 według planu. Po każdym zadaniu testy, ruff,
sprawdz, wpis w raporty/kalibracja/dziennik.md, POSTEP.md, commit i push. Po B4 zatrzymaj się
i daj mi podsumowanie pomiaru startowego.
```

## Po przeczytaniu raportu z części A i pomiaru startowego
```
Wdróż z raportu raporty/analiza_gracza.md pozycje: [numery]. Dopisz je do POSTEP.md jako U1, U2…
i rób po kolei, każdą z testem, commitem i pushem.
```

## Sesja 3 – B5 (gospodarka i trudność)
```
Wykonaj B5 według zadania/B_kalibracja.md. Na końcu nie przechodź dalej: pokaż mi tabelę zmienionych
liczb (stara, nowa, powód) i wyniki trudności, i poczekaj na zatwierdzenie.
```

## Kolejne sesje – B6–B15
```
Kontynuuj kalibrację od pierwszego nieodhaczonego zadania B w POSTEP.md, według zadania/B_kalibracja.md.
Zacznij od raporty/kalibracja/dziennik.md.
```
